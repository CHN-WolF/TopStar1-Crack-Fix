# TopStar1 修改方法

本工具可以放在任意位置，**不需要**放进游戏安装目录。

目录结构如下：

```text
TopStar1-Crack-Fix\
  一键生成Client.bat
  Client.exe          生成后的补丁程序会输出到这里，复制到游戏目录覆盖原文件即可
  程序\
    Client.exe        bemaniso 发布的不完美破解版（作为补丁基础，只读，不要覆盖）
  脚本\
    apply_client_patches.py
  docs\
    README.md
    修改方法.md
```

不要把生成出来的文件拷回 `程序\Client.exe`。`程序\Client.exe` 不是原版程序，而是 bemaniso 上面发布的不完美破解程序，本工具每次都基于它重新打补丁；一旦被覆盖，下次生成会失败。

仓库中已自带 `程序\Client.exe`，下载后可直接双击 `一键生成Client.bat`（或直接运行 `python 脚本\apply_client_patches.py`）。

本机需要安装 Python 3。双击 `一键生成Client.bat` 后，它会调用 `脚本\apply_client_patches.py`，用 `程序\Client.exe` 生成补丁，并在本目录输出 `Client.exe`。窗口会停住，能看到是否生成成功。生成后先关掉游戏，再把生成的 `Client.exe` 复制到游戏根目录覆盖原来的 `Client.exe`。

这个目录做两件事：没有 COM1 也能进游戏，以及 `Addsong` 里的自制歌曲能被读出来。两件事都由同一次生成完成。

## 去掉 COM1 才能进游戏

游戏实际加载的是 `Pack\config.pak`。里面的 `IOBOARD_PORT` 是 `COM1`。本机没有这个口时，以前要装一对虚拟串口，让游戏这边看到 COM1，否则启动失败。`IO\io_emulator.py` 是原来的变通办法，补丁打上之后不用再开它，也不用再装虚拟 COM1。

卡住的地方有两段，只改第一段仍然黑屏。

`CSerial::Create` 在虚拟地址 `0x44FDC0`（文件偏移 `0x4FDC0`）。它打开配置里的端口，失败就返回 0，后面的启动不再继续。原来开头五个字节是 `53 8B 5C 24 08`。改为 `B0 01 C2 04 00`，也就是 `mov al, 1; ret 4`。函数直接告诉调用者打开成功，不再调用 `CreateFile`。

只做这一处时，窗口还是黑的，主线程无响应。`CSerial::Update` 里的写端口在虚拟地址 `0x450480`。`WriteFile` 失败后，代码读保存的错误码：`0x3E5`（`ERROR_IO_PENDING`）会去等，错误码 `0` 也走同一条。等待点在虚拟地址 `0x4504F8`（文件偏移 `0x504F8`），接着调用 `GetOverlappedResult`，并且 `bWait` 为 `TRUE`。没有真实完成的重叠写会在这里一直停着。原来六个字节是 `8B 0D 2C 36 5A 00`。改为 `EB F3 90 90 90 90`，短跳到 `0x4504ED`，那里立刻 `xor al, al; ret 4`。写失败就返回，不再等待。

两处都要留着。打开函数负责让没有 COM1 也能过启动检查。等待点负责让主线程不被假的挂起写堵住。投币和按键仍来自 IO 板，这个补丁不模拟按键。

## 游戏原来为什么不读自制歌曲

自制 pak 放在游戏目录的 `Addsong`。扫描函数会找出里面扩展名正好是 `pak` 的文件。真正挡住的是后面三件事。

1. 打包配置里 `ADDSONG_FROM_USB` 为真。路径函数因此不走当前目录下的 `addsong`。文件偏移 `0x476BD` 原来是 `0F 84 FE 00 00 00`（条件跳走本地路径）。改为 `E9 FF 00 00 00 90`，无条件走到本地路径 `当前目录\addsong`。
2. 一首歌的 `info.csv` 打不开时，打开列表的函数直接返回，后面的 pak 都不再读。文件偏移 `0x47C3E` 的 `74 12` 改成 `90 90`。失败只跳过这一首。
3. 自制包的目录解密和官方包不是同一套用法。解包算法在 `pak to TopStar2 pak\脚本\extract_topstar1_pak.py`。`--list` 能列出真实内部路径。官方 `config.pak` 启动时只用到第 0 项，所以游戏原来的解密能进主界面。自制包的 `info.csv` 不是第 0 项，按旧算法解出来的内部名对不上，查找失败。57 个包都会被打开，但一首都加不进列表。

歌曲列表没有解锁字段。看不到自制歌曲，是因为它们没有进入列表，不是因为被锁住。

## 目录解密

每个目录项 0x98 字节。和提取脚本一致的规则：

- 这一项的标志 = 文件头标志减去该项序号。序号从 0 开始。只使用文件头上的同一个标志，只能解对第 0 项。
- 密钥字节不是 ikey 表里那个固定值。从 0 试到 255，用游戏自己的 `0x458040` 和 `0x457FC0` 解这 0x98 字节。第一个解出来像路径的字节才采用：长度至少 5，含 `\` 和 `.`，字节在 0x20 到 0x7E。一个都不像路径时，退回原来的 ikey 低字节，官方包仍按原样工作。
- 名字在项内偏移 0x0C。游戏查找的是 `歌曲名\info.csv`。现有格式串 `%s/info.csv` 在名字解对之后就能对上，因为比较前会把字母转成小写，并把 `/` 换成 `\`。

补丁放在 `.ikey` 末尾，从虚拟地址 `0x683F00` 起。`.ikey` 原来的虚拟大小盖不住这段代码，所以把虚拟大小扩到代码结束，原始大小按文件对齐扩到 `0x2000`，`SizeOfImage` 改为 `0x285000`。节区属性不变。代码不写自己所在的节区。状态字节放在可写数据区：

| 地址 | 用途 |
| --- | --- |
| `0x681AD0` | 文件头标志 |
| `0x681AD1` | 当前项序号，每个包开始时清零 |
| `0x681AD2` | 正在试的密钥字节 |
| `0x681AD3` | 没有试中时用的原来那个字节 |
| `0x681AD4` | `infor.csv` 是否已经重试过 |

三处调用：

| 文件偏移 | 原指令 | 调用 |
| --- | --- | --- |
| `0x5845F` | 保存标志和文件位置 | 记住标志，序号清零 |
| `0x5851C` | 取 ikey 字节并让 esi 指向原始项 | 试出密钥字节，esi 仍指回原始项 |
| `0x58529` | `cl = 标志`，然后做 0x26 轮表异或 | `cl = 标志 - 序号`，然后序号加 1 |

顺序不能换。选密钥时序号还没有加。表异或时才加。这样第 0 项用文件头标志，后面每一项减 1，和提取脚本的 `flag - index` 一致。

`0x5851C` 原来是 `lea esi, [esp+0x28]`，取的是缓冲区地址。洞穴里对应的是 `lea esi, [ebp+0x38]`。写成 `mov esi, [ebp+0x38]` 会把密文前四个字节当成指针，游戏启动即崩溃。

## 文件名是 infor.csv 的包

35 个包的表叫 `info.csv`，和游戏查找的名字一致。另外 21 个包的表叫 `infor.csv`，目录名本身和 pak 文件名一致。文件偏移 `0x47D80` 改成跳到 `0x684030`。`info.csv` 找不到时，用虚拟地址 `0x684018` 的格式串 `%s/infor.csv` 再找一次。找到就继续解析，两次都没有就按原来的失败路径返回。

## Never Ever

这个包的内部目录是 `Never  Ever`，两个空格。文件如果叫 `Never Ever.pak`，只有一个空格，查找字符串是 `Never Ever\info.csv`，对不上。把 `Addsong` 里的文件手工改名为 `Never  Ever.pak`（`Never` 和 `Ever` 之间两个空格）。不要改回一个空格。这不是解密问题，重打包才能改内部目录，改文件名就够。

## 改完之后

重新启动游戏。原有 27 首还在。`Addsong` 里 57 个自制包都能进入列表：35 个直接找到 `info.csv`，21 个靠 `infor.csv`，`Never  Ever.pak` 靠两个空格的文件名。列表一共 84 首。
